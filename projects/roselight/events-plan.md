## The product

A fully-automated **"This Weekend: 10 Picks"** module — homepage widget + a
section in the weekly "This Week in PDX" digest. **Not** a comprehensive public
calendar. Differentiation is ruthless AI selection, which is the site's brand;
comprehensiveness competes with entrenched incumbents (Everout/WW/Mercury) at
their strongest and multiplies the unattended-failure surface ~20×.

A thin public `/events` page is a **conditional Phase 3**, earned only by
engagement data (see phasing), justified as reader utility — not SEO. (Ruling:
event-page SEO is a dead thesis in 2026; Google's Events panel is fed schema.org
directly from ticketing platforms/venues, and auto-expiring pages on a
low-authority domain compound nothing.)

## Hard constraints

1. **No recurring human involvement.** Humans act on alerts only. No pending
   queues, no editor dashboard, no weekly picking duty. The Sunday digest
   preview remains as a circuit breaker, not a workflow step.
2. **Consent-based sourcing only.** Ingest only what a source affirmatively
   publishes for machine consumption: RSS, ICS, JSON APIs, schema.org/JSON-LD
   markup. **No HTML scraping, no LLM page-extraction at launch.** Always link
   out; per-event source attribution.
3. **Fail-loud beats taste.** Deterministic parsers (ICS/JSON/JSON-LD) that
   crash or 404 visibly are preferred over anything that can silently emit
   plausible garbage. Wrong-date asymmetry: a reader who shows up on the wrong
   night blames The Rose Light, not the source.

### Tier B — venue-direct music & comedy (Phase 1–2) ⭐ *added 2026-07-03*
Live music and comedy are the categories readers most want and Tier A covers
worst. Venue calendar pages nearly all embed **schema.org/JSON-LD Event markup**
(usually generated by their ticketing platform — Etix, TicketWeb, AXS, DICE,
Ticketmaster). JSON-LD parsing is deterministic — no AI, survives redesigns —
and markup published for Google is published for machines (consent-clean).

### Everout / Willamette Week / Portland Mercury
**No ingestion without an affirmative yes.** Scraping a curation product

aggregator. Phase 0 sends a partnership email to EverOut (portland@everout.com)

curating raw feeds, their curation is desirable, not load-bearing.

## Automated quality gates

Built in Phase 1, mandatory before anything is public:
- **Per-source watermark alert:** yield <20% of trailing average for 2
  consecutive syncs → auto-pause source + alert.
- **Canary metrics:** per-source event count, field-completeness,
  date-distribution drift.
- **Auto-expiry:** events disappear at `startDate` absent reconfirmation.
- **24h-pre-start re-verification:** re-fetch each published pick from its
  source within 24h of start; 404 or date-moved → unpublish + alert.
- **Volume floor:** <10 pick candidates → the module hides itself entirely and
  alerts (never renders thin).
- **Nightly synthetic check:** module renders ≥5 future events.
- **Dedup:** merge only on title+venue+exact-date; all ambiguity → keep both.
  (No embedding/fuzzy merging — conflates recurring series.)
- **Scoring:** Haiku, binary approve/reject. No `pending` state anywhere.

## Salvage from the March branch

Keep: `Event` schema (regenerate migration on current main; drop `pending`,
editor fields, venue-alias table), `ParsedEvent` types, enrichment prompt
starting points, card UI as reference. Discard: both HTML scrapers, dedup
fuzzy-matching, editor dashboard, `imageData` Bytes-in-Postgres (shared-host
blast radius — link out or filesystem-cache instead).

## Phasing (each shippable, solo-dev sized)

| Phase | What | Exit criteria |
|---|---|---|
| **0** (days) | Send EverOut email (after owner approval); regenerate migration from trimmed schema | Email sent; migration merged |
| **1** (1–2 wks) | Shadow ingestion: Tier A + first Tier B venues; Haiku scoring; all gates live; **publishes nothing** | 2 clean weeks of canary metrics; ≥30 approved candidates/week |
| **2** | Public 10-picks module: homepage widget + digest section, attribution + link-out | Gates green; go-live |
| **2.5** (conditional) | Tier C APIs for category gaps (music/comedy volume) | Only if volume floor or category coverage demands it |
| **3** (conditional) | Thin public `/events` list + detail with JSON-LD markup | Only if digest events-CTR ≥ news-link CTR after 8 weeks |

## Kill criteria (measurable, no judgment calls)

- Digest events-section CTR < 50% of news-link CTR after 8 weeks → remove module.
- ≥2 user-visible wrong-date/cancelled-event incidents in any 30 days →
  module auto-hides; rearchitect or kill.
- Maintenance > 2 hours/month for a full quarter → kill (hours are the scarce
  resource, not API dollars).
- Approved candidate volume < 30/week for 4 weeks → too thin to curate
  honestly; kill or land the Everout partnership before retrying.
